# FileKV v4.0 重新定位：AI Agent 原生持久化层

**更新日期**: 2026-04-16  
**版本**: v4.0  
**状态**: 战略调整

---

## 一、战略调整背景

### 1.1 之前的错误定位

❌ **"FileKV 要做通用 KV 存储，必须全面超越 RocksDB"**

这个定位导致：
- 追求不切实际的性能数字（100K 写入 161x → 50x）
- 优化目标与真实使用场景脱节
- 投入产出比低（RocksDB 有 10+ 年、数百人年优化）

### 1.2 正确的定位

✅ **"FileKV 是 AI Agent 的原生持久化上下文存储"**

从 try-tokitai 项目看，FileKV 的真实使用场景：
- **AI 助手对话上下文管理**（持续追加、时间线查询）
- **Git 分支式上下文**（fork/merge/time-travel）
- **工具调用缓存**（热点数据、TTL 淘汰）
- **自主进化状态持久化**（checkpoint、恢复）

## 二、AI Agent 工作负载特征

### 2.1 典型操作模式

| 操作 | 频率 | 数据特征 | 性能要求 |
|------|------|----------|----------|
| **追加对话** | 高（每秒 1-10 次） | 小 value（1-10KB），顺序写入 | 延迟 < 100µs |
| **分支创建** | 中（每分钟 1-5 次） | 复制上下文状态 | 延迟 < 10ms |
| **时间旅行** | 低（按需） | 范围查询历史 | 延迟 < 1ms |
| **加载最近对话** | 高（每次交互） | 范围查询（最近 N 条） | 延迟 < 5ms |
| **工具缓存查询** | 极高（每次调用） | 热点 key，TTL 淘汰 | 延迟 < 50µs |
| **上下文合并** | 中（分支合并时） | 批量写入 + 删除 | 吞吐 > 100K entries/s |

### 2.2 与通用 KV 的差异

| 维度 | 通用 KV | AI Agent 上下文 |
|------|---------|-----------------|
| **写入模式** | 批量随机写入 | 持续顺序追加 |
| **读取模式** | 随机点查 | 热点 + 范围查询 |
| **数据规模** | 10M-100M keys | 100K-1M keys（单次会话） |
| **延迟敏感** | 吞吐优先 | 延迟优先（交互体验） |
| **部署方式** | 独立进程/嵌入式 | 纯嵌入式（零配置） |

## 三、重新定义成功指标

### 3.1 不应该比的指标

| 指标 | 原因 |
|------|------|
| **100K 批量写入速度 vs RocksDB** | AI Agent 不会批量写入 100K，而是持续小批量 |
| **纯随机读延迟** | AI Agent 有热点模式（最近对话），不是纯随机 |
| **10M 规模性能** | 单次会话上下文通常 < 1M keys |

### 3.2 应该优化的指标

| 指标 | 当前（估计） | v0.9.0 目标 | 对 AI Agent 的意义 |
|------|-------------|-------------|-------------------|
| **单条对话追加延迟** | ~200µs | < 50µs | 用户输入响应速度 |
| **分支创建延迟** | ~50ms | < 5ms | 平行探索交互体验 |
| **时间旅行查询** | ~10ms | < 1ms | 回溯历史对话 |
| **加载最近 N 条对话** | ~5ms | < 1ms | 上下文恢复速度 |
| **工具缓存查询** | ~100µs | < 20µs | 工具调用延迟 |
| **内存占用（100K keys）** | ~200MB | < 50MB | 嵌入式部署资源 |
| **启动时间** | ~500ms | < 100ms | AI Agent 冷启动 |

## 六、长期愿景（v1.0+）

### 6.1 差异化优势

| 优势 | 描述 | RocksDB 对比 |
|------|------|-------------|
| **Rust 原生** | 零 FFI、类型安全、async 友好 | C++ FFI 开销 |
| **配置简单** | 4 个预设，开箱即用 | 100+ 参数调优 |
| **AI Agent 语义** | 分支、时间旅行、会话 | 无原生支持 |
| **嵌入式部署** | 单二进制，零依赖 | 需要编译、链接 |

### 6.2 目标用户

- ✅ **AI Agent 框架开发者**（需要持久化上下文）
- ✅ **Rust 生态项目**（需要嵌入式 KV）
- ✅ **中小规模部署**（< 1M keys，< 1GB 数据）
- ❌ **大规模生产 KV 存储**（建议用 RocksDB/TiKV）
